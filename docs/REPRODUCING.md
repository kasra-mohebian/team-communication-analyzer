# Running the demo and the research pipeline

## Tested public path

Use requirements-demo.txt and run `python src/demo.py`. This is an offline feature/network demonstration using fictional messages and lexical fallbacks. It needs no real export, API key or trained model. Run `SOCIALCOMPASS_OFFLINE=1 python -m unittest discover -s tests -v` for the regression checks.

## Research prerequisites

The full requirements.txt records optional research dependencies; it is not an exact lockfile of the historical run. Install it separately only if you need neural features, teacher labelling or model comparison. Python 3.12 is tested for the core demo; a full fresh installation of every optional research backend is not certified.

Obtain authorised source data using DATA.md. Configure config/team.json locally, then run the matching parsers. Do not upload that map or those transcripts. Slack parsing also exposes parse_slack(data_root) without reading files on import.

```sh
python src/parse_slack.py
python src/parse_nankani.py
python src/parse_mbada.py
python src/parse_whatsapp.py
python src/make_synthetic.py
python src/build_base_features.py
```

The base builder supplies the previously missing training_results.json and, if a local team export exists, wa_features.json. Synthetic label augmentation is idempotent.

Before training, supply valid private external soft labels in data/labels/opus_labels.json. The existing teacher CLI supports Slack and Nankani; the nine historical Mbada labels are not publicly supplied or generated by that CLI. A complete replacement protocol for those labels must be documented by the researcher. `opus_labeler.py` uses a paid external service and transmits message excerpts; it is deliberately not an automatic step in these instructions. The original teacher model name may also need a currently supported replacement, which creates a different experiment.

```sh
python src/label_synthetic.py
python src/build_v2_features.py
python src/train_ml.py --metric-w 0.5
```

The original five-person reference labels are private. To run compare_holdout.py, independently create an authorised reference for the same local members and document its protocol. Human–teacher agreement additionally needs a private answer key and numeric annotations; no per-user annotation tables are distributed in this edition.

```sh
python src/compare_holdout.py
python src/analyze_agreement.py --returned LOCAL_RETURNED_CSV_FOLDER --answer-key LOCAL_ANSWER_KEY
python src/publish_results.py --public-dir outputs/runs/EXPERIMENT/public
python src/publish_results.py --check --public-dir outputs/runs/EXPERIMENT/public
```

The public exporter selects training-wide fields only and checks the destination against the publication allowlist. Individual outputs from research scripts stay local and must not be added to the public repository. The committed summaries are historical evidence, not a scratch area. Full model retraining has not been rerun in this edition.

## Archived experiments and reporting tools

Scripts in archive/ are retained as historical implementation references. They expect local intermediate results, figures and optional dependencies that are not distributed; they are not a supported way to reconstruct the original report from this public subset. Their original numerical prose does not establish results for corrected code. When inspecting an archived script, note that its imports expect src/ on Python's module search path. Do not publish generated reports containing individual outputs.

## Optional research dependencies and models

The optional research requirements were updated after a dependency review (NLTK 3.10.3, sentence-transformers 5.6.0 and torch 2.13.0). They are not a lockfile of the original experiment. The offline demo has separate requirements and does not load these models. A full neural training run with this revised stack has not been validated; do not label it a reproduction of the historical scores.

Model IDs and exact revisions for future runs are in `src/model_revisions.py`; remote custom code is disabled. Pinning improves traceability but does not make an untrusted model safe. Load only reviewed models from trusted sources, and never deserialize an untrusted joblib/pickle file. Earlier model-cache revisions are unknown. See [security notes](../SECURITY.md).
