# Data availability & provenance

**No raw message corpus is redistributed.** Only selected training-wide aggregate summaries remain in outputs/public; individual records are excluded. `data/` is git-ignored in
full — the corpora contain other people's messages, and one of them is ~890 MB,
far above GitHub's 100 MB per-file limit. This document is what makes the
pipeline reproducible without shipping the data: where each corpus comes from,
what the parser expects, and what it produces.

This is upstream data provenance. Use REPRODUCING.md for this edition's corrected run order and the private-label prerequisites.

---

## 1. Slack — MSR 2020 developer chats · *training*

| | |
|---|---|
| Citation | Chatterjee, P., Damevski, K., Kraft, N. A., Pollock, L. (2020). *Software-related Slack Chats with Disentangled Conversations.* MSR 2020 |
| Source | <https://github.com/preethac/Software-related-Slack-Chats-with-Disentangled-Conversations> |
| Licence | as stated by the dataset authors |
| Full size | 437,893 messages · 12,171 users |
| Used here | 60,000 messages · 1,639 users (Python, Clojure, Elm, Racket channels) |
| Identities | already pseudonymized upstream (given-name handles: `Joey`, `Porsha`, …) |

```bash
git clone https://github.com/preethac/Software-related-Slack-Chats-with-Disentangled-Conversations.git \
          data/raw/slack_data
python src/parse_slack.py          # → data/clean/slack_clean.json
```

The XML supplies conversation ids from upstream disentanglement. They are useful grouping metadata, not ground-truth reply-to links. The corrected v2 fallback isolates available channel/conversation contexts.

## 2. Nankani 2020 — CODERS WhatsApp group · *training*

| | |
|---|---|
| Citation | Nankani, T. (2020). *WhatsApp Chat Export — CODERS Group, TSEC Mumbai.* |
| Type | real WhatsApp group of CS/IT engineering students |
| Size | 11,460 messages · 148 users (Jan–Oct 2020) |
| Identities | **not** pseudonymized upstream — display names are real full names |

Place the export at `data/raw/Nankani_2020.txt`, then:

```bash
python src/parse_nankani.py        # → data/clean/nankani_clean.json
```

> ⚠️ Because the display names are real, `data/clean/`, `data/features/` and
> `data/labels/` are all git-ignored: `opus_labels.json` would otherwise pair a
> real full name with a behavioural judgement about that person. Only aggregate
> statistics derived from this corpus are published.

## 3. Mbada 2023 — professional WhatsApp group · *training*

| | |
|---|---|
| Citation | Mbada, C. E. et al. (2023). WhatsApp group of Nigerian physiotherapists, published as a Word document |
| Size | 529 historical clean messages · 95 participants |
| Identities | **pseudonymized by the original authors** (`Anon 1`, `Contact 2`, …) |
| Why included | Slack and Nankani are technical Q&A and contain almost no Butterfly (information bridge) or Capybara (warm supporter) behaviour. This group is professional-but-social — congratulations, condolences, link sharing — and supplies exactly those two rare classes. |

Place the `.docx` in `data/raw/` (any name matching `Mbada*.docx`), then:

```bash
python src/parse_mbada.py            # → data/clean/mbada_clean.json
python src/parse_mbada.py --verify   # compare against an existing clean file
```

### Known limitation — synthetic timestamps

The document records a **time of day but no reliable continuous date**, so true
inter-message gaps cannot be recovered. `parse_mbada.py` emits a synthetic
60-second ladder (0, 60000, 120000, … ms), which is what the committed feature
matrix was built from.

**Consequence:** these timestamps are invented. They can affect inferred timing/interaction features and must never be interpreted as real response behaviour.
They remain comparable *within* the dataset because rank-normalization is done
per dataset, but **no timing claim should ever be made about Mbada.** Content,
text-style and mention-graph features are unaffected.

`parse_mbada.py` reproduces **528 of the 529 messages (99.8 %)** of the clean
file the shipped results were built from; the single difference is a whitespace
merge in one very long forwarded message.

## 4. Synthetic in-domain team chats · *training, disclosed augmentation*

Generated by this repository — no external source, nothing private.

```bash
python src/make_synthetic.py             # → data/clean/synthetic_clean.json
python src/label_synthetic.py            # fixed soft-label distributions; human versus LLM-assisted authoring is not documented for the synthetic users
python src/build_synthetic_features.py   # feature rows
```

53 users across 9 small-team chats, written to fill the Butterfly/Capybara gap.
Fully disclosed, ablatable with `python src/train_ml.py --no-synthetic`, and
**never** part of the held-out test. Rationale, guardrails and the ablation:
[SYNTHETIC_AUGMENTATION.md](SYNTHETIC_AUGMENTATION.md).

## 5. Private case study

The original course project also evaluated a private team chat. This public edition excludes that corpus and all individual or small-team outputs. A local configuration template is provided for authorised research; it is not the original identity map. No public-publication consent is inferred from coursework participation.

## 6. Garimella — considered and rejected

`Garimella, K. & Eckles, D. (2020), Indian WhatsApp public groups`
(6.3 M messages, ~890 MB) is wired into `config.py` and
`archive/exploratory_scripts/parse_garimella.py` but is **deliberately excluded
from training**: it is broadcast/forward/propaganda traffic from public groups,
i.e. real data that is catastrophically off-domain for *team* archetypes. It was
evaluated and rejected in favour of the disclosed synthetic augmentation; see
[SYNTHETIC_AUGMENTATION.md](SYNTHETIC_AUGMENTATION.md) for the comparison.
